# STEADY docs

Every project document lives here. Only `README.md` (the GitHub front page) and `CLAUDE.md`
(which Claude Code loads from the repo root) stay at the top level.

| Path | What it is | When to open it |
|---|---|---|
| [`STATUS.md`](STATUS.md) | Live state: what's built, pending and broken | First, for anything about *what exists today* |
| [`BUILD.md`](BUILD.md) | How to build, sign and ship the app | Before any EAS or Play Console work |
| [`NOTIFICATIONS.md`](NOTIFICATIONS.md) | The notification system and its message catalogue | Touching reminders, events or copy. The catalogue is generated by `scripts/gen-notification-docs.py` |
| [`journal/DEVLOG.md`](journal/DEVLOG.md) | The build-in-public story, oldest first | After every meaningful action (Rule 1) |
| [`journal/LEARNING.md`](journal/LEARNING.md) | Concepts explained as we met them | After explaining something new (Rule 2) |
| [`testing/TESTING.md`](testing/TESTING.md) | Manual checklist, reset per build | Each test round |
| [`testing/TEST_SCENARIOS.md`](testing/TEST_SCENARIOS.md) | The durable test spec that automated tests trace to | Writing or reviewing tests |
| [`testing/MODEL-TESTING.md`](testing/MODEL-TESTING.md) | How we test AI models and prompts, plus a dated results log | Before any model or prompt change; add an entry after every test |
| [`research/reports/`](research/reports/) | Finished research reports | Product and redesign decisions |
| [`research/notes/`](research/notes/) | Raw notes behind each report, one folder per report | Checking a report's sources |
| [`archive/`](archive/) | Superseded trackers, kept for their root-cause writeups | Rarely |
| `social/` | X and LinkedIn post drafts. Gitignored, never committed | When a story passes the post bar in `CLAUDE.md` |

Plans and design memory for Claude sessions live in `.claude/plans/` and `.claude/memory/`
(gitignored).
