# supabase/pending — migrations that must NOT go out with the next `db push`

`supabase db push` applies every file in `supabase/migrations/` that the database has not seen, in order. A push meant
for 054 would therefore also apply anything numbered after it. The files here are kept out of that folder on purpose:

| File | Generated by | Why it waits |
|---|---|---|
| `055_usda_local_foods.sql` | `npx tsx scripts/import-usda.ts` | Adds 11,986 verified rows with no key. The deployed functions' FTS query only ignores key-less rows once the FTS guard (`.not('normalized_name','is',null)`, spec (g)1) is deployed; before that, real users would see imported rows. |
| `056_usda_local_portions.sql` | `npx tsx scripts/import-usda.ts` | Needs 055. |
| `057_apple_identity.sql` | hand-written, reviewed | Keys one of 055's rows (`apple`). Runs with or without 056. |

## When to move them into `supabase/migrations/`

Only when BOTH are true (spec (i) rollout step 8):

1. The functions with the FTS guard and the USDA-reuse guard (`macroResolver.ts`: the FTS select filters
   `normalized_name`, and the API-pick reuse ignores key-less rows unless `RESOLVER_USDA` is local or `PORTION_MODE`
   is table) are **committed and deployed**.
2. 054 is applied and verified, and rollout step 8 has been reached.

Then `git mv` them (keep their numbers), regenerate to confirm (`npx tsx scripts/import-usda.ts --check` — update
`OUT` in `scripts/usda/emit.ts` to the new folder in the same commit), push to a local copy with the real CLI first, then
run `psql -f scripts/usda/check_056_determinism.sql` against it.

Rollback scripts stay in `supabase/rollback/` (057 down, then 056 down, then 055 down).
